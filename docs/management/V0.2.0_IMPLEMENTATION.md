## Storage and recovery

`backend/src/migrations/` owns schema changes. Current SQLite schema version is 9.
The schema version is independent of the application build version.
An existing workspace upgrade first creates a backup under `backups/before-schema-*`.
All pending migrations share one transaction. A foreign-key failure rolls back the upgrade.
Startup initializes storage before the queue runner and UI open it. Migration and backup record-count checks reject lost legacy records.
If startup fails, the runner stays paused and Task Center can restore a verified backup into a separate workspace.

Sources use generated filenames under `sources/`. Document versions use generated filenames under `documents/`.
Acquisition flushes and hashes the managed copy before metadata refers to it.
Original files never become generated document versions. Extracted text and proposals remain separate records.
An explicit reconciliation method quarantines unreferenced assets. Startup does not delete crash leftovers.

Backup uses `VACUUM INTO` to include committed WAL data in a standalone snapshot.
Its manifest contains schema, table counts, and hashes for the database and all referenced files.
Restore verifies the backup, copies it into a new directory, and verifies the copy.
The desktop waits for the current worker and releases its storage connection before it switches paths.
`active-workspace.json` identifies the restored copy on subsequent launches. The original workspace remains available on disk.
OS credentials remain outside backup files. A restored workspace can require a new credential on another computer.

The `workspace` Rust binary also provides `backup`, `verify`, and `restore` commands.
The desktop Task Center provides backup creation and verified restore selection.

## Queue and AI behavior

One worker runs tasks serially. A separate heartbeat extends the current lease every five seconds.
The runner records attempts and checks owner, generation, cancellation, and lease before it commits results.
The UI uses events and polling. Navigation does not cancel or retarget tasks.
An interrupted local task can resume. A dispatched AI request with an unknown outcome enters `waiting`.
Cancel followed by Retry cannot send that AI request again. A new request requires a new preview and explicit authorization.

Provider settings accept a compatible Chat Completions endpoint and an explicit model ID.
Model discovery queries the saved server's `models` endpoint. It sends no workspace content.
The credential lives in the OS credential manager. Changing the endpoint or provider clears the previous credential reference.
Provider redirects are disabled. Completion transport has a 20-second timeout and a 2 MB response limit.
Only the central runtime calls models. Opening a page or panel never starts a model call.

Each preview contains exact entity data, its revision, the destination, and the operation request.
The authorization hash covers all these values. A change invalidates the preview.
Company context can include excerpts from three stored website snapshots.
The runtime treats source material as untrusted evidence. It has no model-controlled tool execution.
Model output remains a proposal. Acceptance checks revisions and user overrides.
Document acceptance creates a new immutable version. Submitted references remain unchanged.

The ledger separates operations from attempts. Unknown tokens and costs remain null.
Local endpoint responses record zero provider cost. Remote costs remain unknown without reported or configured prices.
Price snapshot storage exists, but the runtime does not yet calculate estimates from it.
Current logical-operation totals count operations with attempts. Queued operations appear in the AI panel and Task Center.

## Import and research limits

Native acquisition accepts files up to 25 MB. Extracted text has a 1 MB limit.
DOCX extraction limits archive entries and expanded bytes. Macro files are rejected.
The Windows parser runs in a child process with a 384 MB Job Object limit and a 15-second deadline.
Windows OCR processes PNG, JPEG, and WebP images locally. Images are limited to 24 megapixels and resized to the OCR engine limit.
PDF files without a text layer use Windows PDF rendering and OCR, up to 20 pages within the parser deadline.
An installed Windows OCR language pack is required. Unreadable images and unsupported platforms retain a manual transcript path.
Mixed PDFs with both readable text and scanned-only pages currently use their existing text layer. Review the result for missing pages.
Several imports can be combined in selection order into one vacancy. Every original source remains attached.
Public URL fetches reject private network destinations, pin resolved addresses, and limit redirects, bytes, and elapsed time.
Restricted or unavailable pages require paste or file input.
Pages with JobPosting JSON-LD supply their title, employer, location, and readable description without executing page scripts.

Classification uses deterministic keyword rules and preserves uncertainty. The user can correct the entity, category, title, and extracted content.
Supported vacancy fields include original salary text. Missing currency and dates remain unknown.
Import review commits the target and source links in one transaction. Repeated saves return the same target.
PDF/DOCX exports represent selected version text. They do not reproduce the imported file's original layout.
The PDF embeds Noto Sans under its bundled OFL license. Unsupported glyphs produce an explicit error.

## Resume to application documents

Use Universal Add to import an existing PDF or DOCX resume and save the review as Resume.
Import a vacancy from text, a public URL, or screenshots. Review its role and company before saving.
Prepare documents on the vacancy creates a separate resume copy or cover letter template from the selected resume version.
The AI panel includes the original resume, vacancy, current document, and profile in its explicit preview.
Manual editing and PDF export work without an AI provider. AI generation requires a configured compatible endpoint.
See the [document workflow guide](../guides/APPLICATION_DOCUMENTS.md) for the exact controls.
The Settings popover displays the version from the root package manifest.

Website research proposes the URL and description from retrieved metadata.
Broader company insights can use the central runtime with stored evidence, followed by explicit proposal review.
Refresh does not overwrite current facts. Local logo replacement validates dimensions, decodes the image, and stores a normalized PNG.
A failed logo replacement preserves the previous asset. Company merge preserves sources, logos, history, and application stages.

## Build and continuation

`scripts/build.mjs` reserves one build increment and synchronizes all version files before a frontend or native build.
A nested Tauri frontend build uses the same reservation. A failed build restores the previous version values.
The application minor version is now 0.2 because the desktop exposes several new product surfaces.
