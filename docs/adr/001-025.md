# Decisions 001-025

## Decision 001: Application stack

Date: 2026-09-13.

Status: Accepted by the user.

### Context

CowWorker requires desktop applications for Windows 11 and macOS. Its planned features include document editing, AI assistance, and system integrations.

The discussion compared Qt with C++, Tauri with React and Rust, and Avalonia with C#.

### Decision

Use Rust, React, TypeScript, and Tauri as the primary application stack.

The user accepted TypeScript in the follow-up discussion on the same date.

Rust owns application logic and system integrations. React owns the user interface. Tauri connects these layers and provides the application shell.

### Consequences

The primary application will not use Qt or C++. Future implementation work will follow the selected stack.

Decision 002 defines the storage direction. Editor libraries, AI providers, the server implementation, and dependency versions remain open decisions.

This record documents a technology choice. It does not establish a working application or verified platform support for CowWorker.

See [the stack document](../tech/STACK.md) for proposed additions and open decisions.

## Decision 002: Local storage and server synchronization

Date: 2026-09-13.

Status: Accepted by the user.

### Context

CowWorker requires local work without an internet connection and a path to use across multiple devices.

### Decision

Use SQLite on each device for application data. Store original documents as separate files. Synchronize data between devices through a server.

### Consequences

Local work must not depend on server availability.

The database schema, file layout, synchronization protocol, conflict rules, document transfer, backup, and encryption require further decisions.

The server language, server database, and deployment details remain open decisions.

This record defines the storage direction. At the time of this decision, storage and synchronization were not implemented.
Decision 004 records the subsequent local implementation. Server synchronization remains open.

## Decision 004: First local workflow

Date: 2026-09-13.

Status: Implemented under the user's autonomous execution instruction.

### Context

The repository had an accepted stack, storage direction, and visual reference, but no application code.
The user instructed implementation with maximum autonomy and commits for substantial changes.

### Decision

Use an npm workspace root with React and TypeScript sources in `frontend/`, a Tauri 2 shell in `src-tauri/`, and a separate Rust library in `backend/`.
Use Vite for the frontend build and rusqlite with bundled SQLite. Commit both dependency lockfiles.

Implement manual vacancy capture, local profile facts, immutable text document versions, application stages and history, and next-action dates first.
Allow one application per vacancy in this schema. Preserve submitted document version references.
Keep browser demonstration data separate from desktop SQLite. Keep development data separate from release data.

### Consequences

This is a working first slice, not completion of the full concept.
AI, document parsing beyond UTF-8 text, synchronization, external platform integrations, and mobile delivery require subsequent work.
The Windows build is checked locally. macOS requires a separate build host and native validation.

See [data model](../tech/DATA_MODEL.md) for state, version, migration, and failure rules.

## Decision 005: Contextual workspace and planned runtime boundaries

Date: 2026-09-13.

Status: Product requirements supplied by the user. Engineering choices adopted for planning, not implemented or separately approved as shipped behavior.

### Context

The user requested contextual AI, Universal Import, independent companies, background tasks, consistent AI Operations, and central AI Usage.
The current implementation provides a manual local workflow with one application per vacancy and immutable text versions.

### Decision

Use [Product](../business/PRODUCT.md) as the current requirement source and [Architecture](../tech/ARCHITECTURE.md) as the contract source.
Plan a persistent Rust task runner, source/candidate/override ownership, independent Company identity, and one AI operation/attempt ledger.
Keep task status and contextual AI at shell lifetime. Persist safe recovery across restarts without promising execution after process exit.
Preserve submitted versions and the existing application uniqueness constraint.
Place migration compatibility and backups before automated writes. Keep providers, parser dependencies, and external-account selection outside this decision.

### Consequences

The original concept remains historical. Requirements do not indicate completed features.
The [development plan](../management/V0.2.0_DEVELOPMENT_PLAN.md) defines phased changes and verification gates.
No production code changes belong to this documentation task.
